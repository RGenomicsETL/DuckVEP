# gnomAD v4.1 staging

The 98-object manifest pins GRCh38 v4.1 genome, exome and SV sites plus indexes by object name, byte length, generation, MD5 and CRC32C. Run `bash scripts/stage_gnomad_v4.1.sh sv`, `bash scripts/stage_gnomad_v4.1.sh exomes chrY`, or `bash scripts/stage_gnomad_v4.1.sh genomes chrY` from this checkout. Repeat with other chromosomes, one at a time. Completed chromosomes are skipped; an interrupted `.partial` shard is discarded and streamed again against the same generation. Raw VCF bytes pass through `curl`, `tee` and `bcftools` pipes, never through a staging file. A shard becomes complete only when the compressed stream's MD5 and byte count match the manifest and its Parquet parts, record/ALT counts and SHA-256 hashes are written.

Parquet corpora live in `/root/duckvep/data/gnomad-v4.1/`; Git contains their manifests and receipts. The source Parquet preserves CHROM, POS, ID, REF, ALT, FILTER, physical record and ALT ordinals, the manifest's source MD5, and the region index resolved from the pinned GRCh38 model. ALTs are not normalized or dropped; `literal`, `star`, `symbolic`, `breakend` and `unsupported` are separate statuses. A literal allele requires a mapped contig, A/C/G/T/N on both sides and a changed allele. SV rows retain END, SVTYPE, SVLEN, CIPOS, CIEND, MATEID and EVENT. `scripts/gnomad_sv_geometry.R` records paired, unpaired, missing-bound, imprecise and bounded SV statuses without rewriting source identities. `scripts/gnomad_structural_controls.R` creates a separate 10,000-event reference-anchored control set, including 2,000 paired BND events with 500 of each ALT orientation.

Run `Rscript scripts/gnomad_genome_panels.R` or `Rscript scripts/gnomad_exome_panel.R` after source shards verify. Genome panels use a fixed SHA-256 rank within chromosome/allele-class strata and a distinct-allele deduplication map. Their sources are pinned by checksums in each panel directory; panels from an incomplete source set remain scoped to those sources, not a claim of whole-genome coverage. Exome selection requires 1M CDS SNVs, 500k CDS indels, 100k CDS equal-length multi-base substitutions and 400k remaining splice-boundary ±8-bp alleles, derived from model exon/CDS geometry. A source-class upper bound below quota produces a measured bound; otherwise, insufficient CDS or splice bins produce exact availability. Neither case pads the panel. Run `Rscript scripts/gnomad_staging_receipts.R` to verify all completed shards, regenerate FILTER counts and write the committed object, part-checksum and remaining-source inventories. The source and selected outputs share a 25 GB staging cap; leave at least 40 GB free for concurrent work.
