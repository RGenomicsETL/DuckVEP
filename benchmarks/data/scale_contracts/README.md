# GRCh38 scale contracts

Run `Rscript benchmarks/scale_contracts.R` from the repository root after `make release`. The check loads the model at `/root/duckvep/data/models/homo_sapiens_116_GRCh38_final.duckdb` (override with `DUCKVEP_SCALE_MODEL`) and the local release extension (override with `DUCKVEP_SCALE_EXTENSION`). `inputs.tsv` pins the model bytes, the native source tree, the field-contract query source, the DuckDB runtime and the checked-in canonical-status snapshot. The extension is compiled from the pinned source tree; its binary includes a revision stamp, so output fingerprints, rather than binary bytes, are the executable gate. The snapshot supplies only canonical flags; display metadata not available in this model is NULL.

The complete-17 query uses `query(duckvep_annotate_projected_sql(events, model, options))`. This dedicated builder accepts ordered, literal small-variant events with an `event_index` and preserves source columns for formatting. Its only options are `upstream_distance` and `downstream_distance` (both default to 5000). It selects the projected-facts annotation cursor once, expands the returned list with `UNNEST`, and joins a transcript dimension containing canonical status, stable identifiers and strand once per receipt. The compact query uses `duckvep_annotate_sql`. A dedicated builder keeps the projected presentation contract distinct from the compact/rich annotation relation; it does not add a second projection pass. Model metadata and source events are loaded before annotation, and the formatted rows stream to the receipt sink.

`inputs.tsv` identifies the frozen baseline source tree and field-contract source. The executable gate compares output fingerprints against those baselines while allowing the implementation source to evolve.

`eligibility.tsv` describes the 100,957-site GIAB bench table. A literal allele is eligible when its region maps to the model, both REF and ALT consist of A/C/G/T/N, and they differ after uppercasing. The executable fixture covers equal alleles, non-literal ALTs, invalid bases and unmapped regions. `schemas.tsv` fixes the column order and DuckDB types for the public compact and native-tab 17-field contracts with source identities. The compact results are checked both without regulation and with interval features; complete17 is checked without regulation.

`receipts.tsv` records row counts, full-row DuckDB hash sums and XORs, and 16 SHA-256 digests. Each digest covers a partition of source event identities, sorted by the complete JSON row, encoded as UTF-8 byte-length, colon, row and newline. The JSON includes field names, source identity and explicit NULLs; duplicate rows contribute repeatedly. SHA-256 is independent of the process's row ordering, while the DuckDB hash aggregates also depend on the pinned runtime. A mismatched digest identifies a partition for an exact row-level investigation; the digest alone cannot supply the differing rows.

The `retained_failures` lane checks every cell in the committed `fields_replay_9bf888e/worker-*.parquet` evidence, including both actual and expected strings. It verifies 41,942 disagreement cells from 10,100 replay tasks without deleting any disagreement. This inventory check does not invoke VEP or FastVEP and does not constitute a fresh biological replay. The pinned replay evidence and the benchmark replay driver remain the inputs to a fresh comparison.

## Scale panels

`panels/panel-receipts.tsv` and `panel-shards.tsv` record the gnomAD v4.1 scale panels (built by `scripts/gnomad_build_panels.sh`, documented in `docs/scale-runner.md`). The 2M exome panel is 1M CDS SNVs, 600k CDS indels and 400k remaining alleles within 8 bp of a splice boundary. The gnomAD sites files contain no equal-length multi-base substitutions (0 of 183,717,261 exome alleles), so MNV coverage comes from the existing ClinVar and indel/MNV controls, not from gnomAD; the former 100k CDS MNV quota moved to the indel bin.
